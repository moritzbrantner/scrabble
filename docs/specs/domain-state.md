# Deterministic state storage

`GameState` owns immutable ruleset data, stable seat order, scores, private racks, the ordered bag, committed board tiles, phase, and public revision. Construction validates the ruleset before allocating tiles. Tile IDs follow declared tile-definition order and each tile has immutable face/value/identity. There is no public mutable collection, unchecked deserialization, or automatic canonical serialization to accidentally disclose racks or bypass storage invariants.

Initialization uses the full 32-byte seed with rand_chacha ChaCha8Rng 0.10.0 and rand 0.10.3 SliceRandom shuffle. The shuffled bag draws from its tail; initial dealing is round-robin in seat order. Replacement draws preserve that same order and stop at rack capacity or an empty bag. The lockfile and the seed-seven golden fixture define this initialization version. Shuffle dependency changes must preserve the golden result or deliberately version the initialization/replay implementation; ruleset identity alone does not identify a shuffle algorithm. Production seeds must be unpredictable and never cross a browser connection.

`deal_initial_racks` is a storage-level transition from lobby to playing. It requires a valid admitted roster and cannot run twice. `place_tiles` atomically moves actual owned tiles to empty board cells, validates duplicate IDs/coordinates and blank assignments, and cannot overwrite committed tiles. `refill_rack` moves bag tiles into available rack slots. These methods do not establish command authority, advance turns, validate placement geometry/words, or award scores; the next slices compose them inside an authoritative transaction. An empty storage transfer is a no-op; an empty gameplay commit must later be rejected.

`public_snapshot` emits only public fields in seat and row-major board order. `player_snapshot` adds one explicitly selected rack. The server adapter must supply authenticated identity when selecting that rack. Trusted in-process rack access exists for rules validation and never grants browser lookup authority. `GameState` has neither Debug nor Serialize implementations, reducing accidental canonical-state logging/disclosure.

`verify_tile_conservation` reconstructs the declared inventory and compares every tile identity, face, and value across bag, racks, and board. It rejects missing, duplicated, or altered tiles. This is diagnostic/test evidence; ordinary transfers preserve ownership without duplicating tiles.

The state tests exercise reproducibility through bag exhaustion, the fixed seed-seven deal, a partial final draw, maximum rack/player bounds, configured-board bounds, blank value/assignment, atomic rejected transfers, conservation, and private/public projection boundaries. Run `cargo test -p scrabble-game --test domain_state --locked` for this slice.
