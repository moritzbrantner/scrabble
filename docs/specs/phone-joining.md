# Phone joining and identity

A player invitation opens a compact name/join form after public match availability has been checked. Submitting the form checks `GET /games/<id>/join` for a current lobby and a free runtime slot before attempting transport admission. This read-only hint returns the existing five public join fields and never reserves or allocates a slot. The runtime remains the final admission authority. A raced handshake rejection rechecks current facts so full, closed, expired and unavailable matches remain distinguishable from browser/network failures.

Admission supplies the authenticated player identity. The phone sends a sequenced `set_name` Scrabble command for that identity, waiting for a matching authoritative snapshot before displaying the controller. Rust validates the game, player and sequence claims, lobby phase, and trimmed name of 1–32 Unicode scalars without control characters. Duplicate names are explicitly allowed and retain distinct IDs, racks, ordering and host permission. Invalid commands leave canonical state and revision unchanged. The name command enters the normal replay journal, so names survive recovery. If the host starts during name confirmation, the controller retains its admitted identity and displays the authoritative existing name with an explanatory message.

The phone persists a strict version-one capsule in `sessionStorage` under `scrabble:player:v1:<canonical transport route>`. Its only fields are `version`, `route`, `playerId`, `token`, and `sequence`. Route binding prevents another match or endpoint from receiving the capability. Names, snapshots, racks, bag data and creation intents are not persisted. Local storage, public state callbacks, URLs, invite links and QR codes contain no reconnect credential. Same-origin scripts can access session storage; this is a private browser capability rather than an account session, and application code must keep that storage boundary private.

`BrowserMatch` restores the capsule’s identity and sequence cursor, compares the reconnect welcome against the saved ID, and saves each rotated token before publishing connected state. Sequence reservation is saved before delivery, including delivery failure, so refresh cannot reuse a transmitted sequence. Missing/invalid/expired capabilities never silently allocate a replacement player. Explicit retry preserves the current identity; joining as a new player explicitly closes the old client and clears the route’s capsule. Session storage naturally follows the tab lifetime. The runtime decides reconnect grace and token validity, including after restart. Broader board resume, automatic reconnect/backoff and expired-player game policy remain #26/#27.

The controller validates both the private recipient and the public game ID against lookup, plus installed ruleset/dictionary identity. It displays its own authoritative name and ID, connection status and waiting/turn state. It renders no shared board and no other player’s private data. Rack interaction remains #16/#17.

Validation uses actual Scrabble/WebTransport in Chromium: two isolated phone contexts choose the same name and receive distinct IDs; repeated refresh preserves identity and rotates valid credentials; a full lobby and started game yield different errors; an admitted phone resumes after start without consuming another seat. The phone viewport stays within its width, storage has exactly the required capsule fields, and public URL/local storage remain clean. Rust tests reject identity/host claims through matching names, bound and atomically reject invalid names, and recover renamed game state through replay. Schema tests reject malformed, excessive and cross-match saved claims. Full gate: `bun run check`. Shared convention revision: `46d8793bb3034326561f876dcc67dbaa5aa1e432`.
