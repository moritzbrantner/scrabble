# Built-client multiplayer acceptance

`bun run test:browser` runs the existing development-browser suite, then provisions fresh native fixtures for a built Pages-style client. The second suite builds Vite in explicit test mode into ignored `test-results/pages-build`, serves those static assets under `/scrabble/`, and uses the real game API and authoritative WebTransport server. The normal production output in `dist` is separate.

The test creates a game from the shared board, opens the invite in two independent browser contexts, names both players, starts, and verifies two disjoint private seven-tile racks. A separately configured, authored test list deliberately accepts TA and CTA but rejects AT. The first player submits AT, receives private invalid-word feedback without losing the connection or draft, then commits TA; the next player previews and extends it to CTA. Every client must converge after each commit on the complete public projection, scores, remaining count, and turn. Rack checks establish two replacement identities after TA, one after CTA, and an unchanged other rack. Waiting phones have disabled rack, commit, pass and exchange controls. The active player then previews another tile, opens and cancels pass confirmation, and confirms a pass. Every client must converge on the next turn with unchanged committed board, scores, bag and rack identities, and no tentative preview. The next player stages a draft, enters private exchange selection, toggles tiles, cancels and restores the preview, then confirms a two-tile exchange. All clients converge on the next turn with unchanged board, scores, bag count and other rack. Exactly two selected identities are replaced, and refreshing the exchanging phone preserves the new rack. Four further passes reach the configured scoreless limit. The browser independently totals both private rack values and verifies converged final scores and all highest-scoring winner identities. The final board has no private rack, both phone racks are read-only, all gameplay controls disappear, and refreshing a finished phone preserves the final result. A native negative test submits an owned commit from the non-active player and proves canonical state stays unchanged.

A test-only WebTransport reader observes actual snapshot datagrams before forwarding the unchanged bytes to the built application. The existing wire reassembler and strict domain schema decode them. Every frame must target the expected recipient, and every shared-board frame must contain an empty private rack. Welcome/reconnect credentials travel on the reliable welcome stream and are not inspected. The observer is outside the application import graph and stores no credentials.

The native factory selects creation inputs whose actual seeded deals supply A/T for the first rack and C for the next in the deliberately small authored dictionary. The test list is loaded through ordinary server dictionary configuration and produces explicit content-fingerprinted rules/dictionary identities. No rack, word-list contents or seed key enters metadata, and no gameplay state or projection is replaced. A test helper supplies those creation inputs through the browser's request generator. Endpoint/API configuration is compiled through the same VITE settings used by release builds. Local certificate pinning is compiled only in explicit test mode; ordinary release builds use normal TLS trust. Production routing now honors configured endpoints for board creation and board refresh.

`bun scripts/test-browser.ts --pages` runs the built-client scenario alone. Full gate: `bun run check`; it includes both browser suites. Shared policy sourceRevision: `46d8793bb3034326561f876dcc67dbaa5aa1e432`.
