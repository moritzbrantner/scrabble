# Browser transport

`apps/web/src/transport` consumes [game-server's browser contract](https://github.com/moritzbrantner/game-server/blob/9dbec8198ce8ad1da99aada8659dd7d946e28ef5/README.md#browser-contract): route version 1, game wire version 3, control version 1. `fixtures/wire.json` is a public compatibility artifact generated by the pinned upstream Rust encoders. Its welcome token is synthetic test data.

The endpoint is an HTTPS origin plus canonical base path (for example `https://games.example.com/game`); match IDs use 1–64 ASCII letters, digits, `_` or `-`. Admission addresses `/game/matches/<id>`, and reconnect uses the published `/reconnect/<token>` suffix. Dot segments, encoded segments, credentials, trailing slashes, query strings and fragments are rejected before browser URL normalization.

`BrowserMatch.run()` owns one connection until it ends. `close()` cancels the owner permanently; `disconnect()` ends the current connection while retaining the in-memory capability. A subsequent `run()` explicitly reconnects. The caller observes the run promise and state callbacks. Welcome establishment has a ten-second deadline. A connected latest-state stream deliberately lives until disconnect/cancellation.

`sendCommand(buildPayload)` allocates the next nonzero u32 sequence and passes it and the authenticated player ID to the payload builder. The Scrabble caller uses `encodeGameCommand` to construct protocol-v1 bytes. Payloads must fit both upstream's 1,024-byte limit and the negotiated datagram budget. Sequence reservation precedes asynchronous writing, survives reconnect, and fails at u32 exhaustion. Successful writing means queued datagram delivery, not server acceptance.

Snapshot frames carry big-endian tick/hash u64s and a bounded payload. Hash verification uses the published FNV-1a calculation. Whole snapshots and kind-4 fragments enter `SnapshotReassembler.accept()`, returning one verified frame or no completed/newer frame. Reassembly retains at most four incomplete snapshots and 131,110 bytes, accepts at most 64 fragments per frame, and expires an incomplete snapshot after more than 256 datagrams without storing a new fragment. Duplicate, stale, lost, reordered, inconsistent and malformed frames have focused tests.

`control(payload)` uses a separate bidirectional stream with `GSCT` version-1 framing, a 4,096-byte payload ceiling, stream FIN, exact response length, a five-second deadline and at most four exchanges in flight. Rejections are explicit results. Cancellation aborts the stream; raw browser exceptions are not exposed.

`decodePlayerSnapshot` validates strict Scrabble protocol-v1 snapshots and the private rack's recipient. `ConnectionStatus` renders connecting, connected, disconnected, failed and incompatible states. Development builds accept `?server=<encoded-HTTPS-base>&match=<id>` to show a live public board for the installed English fixture ruleset. This is an explicitly supplied development connection; production endpoint discovery/configuration is #31, phone joining uses the player query route and its dedicated controller; broader reconnect policy remains #26. The public Pages build still opens its board preview.

## Verification

`bun run test:browser` builds and owns a loopback Rust fixture using the actual upstream serving runtime. It creates an ephemeral certificate and an OS-assigned UDP port, passes the certificate SHA-256 digest directly to Chromium's WebTransport API, and removes its temporary certificate/key directory on completion. The fixture has no Scrabble rules: it records command sequence numbers, returns a 12 KB projection, and accepts/rejects/delays control requests.

Chromium proves admission, snapshot fragmentation, datagram command ingestion, reliable control success/rejection/concurrency/timeout, realtime progress during stalled control, reconnect identity and epoch rotation, sequence continuation, and absence of capabilities in public callbacks or page URLs. The dedicated phone tests additionally verify the minimal, route-bound session-storage capsule, repeated refresh with the same identity, and continued resume after play starts. Bun tests verify Rust-produced bytes, protocol versions, framing, integrity, reassembly bounds and application payload validation. Rust tests ensure committed wire fixtures still equal upstream encoder output.

Regenerate the deliberate wire compatibility artifact with:

```sh
cargo run -q -p scrabble-server --example browser_wire_fixtures --locked > apps/web/src/transport/fixtures/wire.json
bun run format
```
