# Private state and untrusted clients

Scrabble treats the authenticated native connection, never a browser payload claim, as the actor. `MatchRuntime` checks the player, live connection epoch, nonzero monotonic transport sequence, and payload byte bound before calling the simulation. `GameSession` then compares the game's identity, claimed player and sequence, current turn, phase, and active seat. Board claims and Start additionally require the separate board authority. A client-supplied tile identity still has to belong to that canonical rack. Preview, commit, and exchange all validate ownership; coordinates, duplicate tiles/squares, rack bounds, blank assignments, and move legality cannot be authorized by the UI.

Every simulation advertises `SnapshotScope::PlayerScoped`. The transport asks for the authenticated actor's projection. Phones get the public DTO and only their own rack; board actors have an empty rack outside the playing roster. Public board and preview tiles carry no tile IDs. The public DTO contains board/preview letters, scores, rack counts, remaining count, phase, content identities, and presence/host metadata; it contains no ordered bag, rack contents/history, private seed, sequence journal, recovery data, or reconnect capability. There is no gameplay command that selects another rack or requests a canonical snapshot. Reliable control uses the native rejection service; it exposes no alternative inspection API. Native canonical snapshot and projection methods are trusted in-process interfaces, not client-controlled selectors.

The runtime bounds a gameplay payload to 1024 bytes before domain decoding; the reusable domain decoder has its own 16 KiB bound and at most 15 tile entries. Versioned strict Serde types reject unknown fields/variants, invalid coordinate or identity representations, malformed UTF-8/JSON, and injected score/authority fields. Domain decode failures use the static diagnostic `invalid command encoding`, without echoing attacker-supplied field names or values. At the application boundary, rejected commands consume neither domain nor runtime sequence, change no canonical state or preview, and add no applied-command replay record. Connection loss independently clears or hides tentative previews and updates presence. An old sequence is ignored by native fencing. Invalid wire/ordinary simulation commands close only the offending connection; invalid-word feedback uses the bounded private rejection stream and keeps the connection usable.

Reconnect token rotation preserves the player and rack while incrementing the epoch. The old epoch cannot submit commands or disconnect the replacement; an old token cannot reconnect again. An expired capability cannot reclaim a retained started seat. Client retries reuse the capability and stop without fallback admission, as described in [reconnect and resume](reconnect-resume.md).

## Diagnostics and durable evidence

`GameState` and `ScrabbleSimulation` expose no derived `Debug` or general serialization. `Tile`, `RackTile`, `PrivateRack`, gameplay commands (including board proofs), and dictionary errors redact private contents in `Debug`/`Display`, while explicit JSON retains the fields needed by scoped clients and deterministic replay. Public metadata and tile/word counts remain available for diagnosis.

The native runtime pin `7decf2c2f101984460b7dda7277cf5aa6039b761` provides redacted diagnostics for reconnect tokens/welcomes, command/rejection/snapshot/control payloads, partial reassembly buffers, simulation snapshots, and replay records. Nested session/recovery diagnostics inherit those boundaries. Wire codecs, equality, hashes, and replay/recovery encoding are unchanged. See [upstream PR #36](https://github.com/moritzbrantner/game-server/pull/36) and its private-diagnostics ADR.

Explicit serializers, raw field access, scoped client payloads, and replay/recovery files still contain private information by design. They must remain within their existing authenticated or private filesystem boundaries. Redacted diagnostic implementations cannot protect deliberately printed raw fields or arbitrary application-authored error text. Browser failures remain sanitized so native errors cannot echo private reconnect URLs. No credentials appear in player invites or public storage/status responses.

## Verification

- Runtime negative tests use actual separate-board factory state and reject other players' tiles, bag tiles, unknown tiles, forged game/player/sequence/turn claims, board gameplay, impossible coordinates, unsupported inspection commands, injected scores, malformed encoding, and oversized messages. Each case preserves every scoped projection, canonical bytes, and replay-record count; a subsequent legal command and replay still succeed.
- Exact public key sets and canonical owner/rack comparisons verify the empty board rack, disjoint private racks, and absence of hidden state. Rotation tests fence the old epoch/token, stale sequence, and stale disconnect without mutation.
- A real executable/WebTransport test sends six forged/malformed wire requests, including a deliberately oversized native frame. Each closes only the attacker, preserves peer gameplay and racks, allows native reconnect, and leaves sequence 2 available for a legal pass. Requests to inspect another rack/canonical state through reliable control receive an empty rejection. Captured stderr contains no private markers, reconnect token, or rack dump, and readiness remains healthy.
- Domain diagnostic tests preserve explicit JSON round-trips while redacting private values. Upstream direct/nested sentinel tests cover native frames, incomplete reassembly, replay, credentials, and a real runtime recovery image. Existing browser suites independently inspect real scoped datagrams and prove private token persistence, refresh, draft reconciliation, and board-empty projections.
