# Authoritative turn application

`GameSession::apply` is the deterministic application boundary for already-sequenced commands. The transport supplies authenticated player identity and sequence separately from the payload; the two must agree. The session then checks game identity, admitted player, monotonic nonzero sequence, phase, expected turn, and active player before any mutation. Rejected commands consume neither sequence nor turn and preserve canonical and preview state.

The first admitted player is the lobby host and alone may start. Start deals once, selects the first seat, and begins turn zero. A pass advances to the next seat and increments the turn without changing board, rack, bag or scores; seat order wraps while the turn number continues increasing. Counter exhaustion fails atomically. The phone exposes a confirmed pass action; full end-game semantics follow in #25.

Preview replacement validates owned tile identities, coordinates, occupied squares, duplicate selections, alphabet/blank assignment, and rack-size bounds through the same storage-validation seam used by transfers. It does not impose commit-time word/line geometry; incomplete drafts can be mirrored. Empty preview cancels. Preview does not remove tiles from the rack or change canonical revision. Turn advancement, accepted disconnect/reconnect notifications, and authenticated runtime removal clear the preview. The simulation adapter also expires unrefreshed previews after two seconds; native runtime presence hides offline previews during recovery. See [tentative preview](tentative-preview.md).

Commit validates structure and every formed word against the match’s immutable configured dictionary, calculates the authoritative score, and atomically transfers tiles, refills the committing rack from the seeded bag, and advances the turn. Preview clearing and sequence admission happen only after success. Rejected words, ownership/geometry errors, score overflow, and exhausted turn/revision counters leave canonical state unchanged. The atomic candidate uses the existing scoring/storage implementation; caller-supplied scores are impossible. Refills stop at rack capacity or an exhausted bag; they are part of the same published result. Deployment lists are loaded and content-fingerprinted once; every formed word must match, and invalid words return structured private feedback without sequence/replay admission. Exchange validates a nonempty, distinct owned tile selection and the configured minimum bag size, draws replacements before returning tiles, reshuffles with the private seed and current-turn stream, and publishes rack/bag/turn changes atomically. It preserves board and scores and clears the preview only after success.

`GameState::canonical_bytes` is explicit private, versioned replay evidence containing full ruleset data, phase, revision, seat order/scores/racks, ordered bag and committed board. It has stable struct/collection ordering and deliberately excludes preview. These bytes must never be sent over a browser snapshot connection. Public/scoped projections remain distinct. Session sequence cursors are command-admission metadata; game-server also maintains authoritative sequence/epoch fencing and persists it in its recovery boundary. Constructing a new session from state alone does not restore transport admission state and is not yet a recovery API.

The tests prove deterministic canonical bytes after every command in a replay, repeated and stale sequence rejection, out-of-turn/identity/game/turn rejection, retry of a rejected sequence, host-only start, draft replacement/cancellation, preservation after invalid drafts, turn rollover, and overflow rejection. Run `cargo test -p scrabble-game --test turns --locked`; overflow is additionally covered by the state unit test.
